# Design-partner runbook

1. Name one business-critical journey, its human owner, and the decision Lyte
   should improve.
2. Define three to ten services, one delivery source, applicable AI agents, and
   two or three outcomes with units, currencies, targets, and truth bases.
3. Connect read-only sources in a private test workspace. Verify access scope,
   data minimization, time windows, retention, and source receipts.
4. Run a known historical incident through playback. Compare evidence capture,
   explanation time, review quality, and outcome verification to the baseline.
5. Permit Hatun to recommend review only. No automatic remediation is part of
   this wave.
6. Export the receipt chain, confirm tenant isolation, and record gaps as
   `UNAVAILABLE` or `ROADMAP` before deciding whether to expand.

Exit criteria are agreed measurements, a named operator, complete evidence,
and a production deployment design. A compelling sample UI is not an exit
criterion.
